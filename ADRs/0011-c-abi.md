# ADR-0011: Publish a C ABI and Python bindings

- Status: Accepted
- Date: 2026-08-14
- Scope: UniMedia
- Supersedes: the foreign-language section of
  [ADR-0003](0003-engine-and-shell.md); its engine/shell split and its thread
  and cancellation contract stay in force.

## Decision

UniMedia publishes a C ABI and a Python extension, in the family layout every
other Uni* library already uses:

```
src/UniMedia/c_api.nim     the ABI
include/UniMedia.h         the header
py/unimedia/_core.pyx      the Cython binding
py/pyproject.toml          the wheel
```

Two reasons, and the second is the stronger one.

**Native applications need to link the engine.** They consume a static library
through a bridging header; driving the `om` executable as a child process is not
a substitute, because a sandboxed application cannot spawn arbitrary helpers.
Without the ABI they cannot use UniMedia at all.

**The family ships bindings.** Every other engine carries `src/*/c_api.nim`,
`include/*.h` and `py/` — UniAccurate, UniImage, UniColor, UniPercept,
UniCrypto, UniVector, UniMath, UniGraph, UniLinalg, UniGeom, UniBarCode and
UniTemplate. UniMedia was the one exception, and being the exception is what
ADR-0003 actually decided. A
catalogue whose data is meant to be reusable by other applications is the last
library that should lack the bindings the rest have.

## What the ABI does not expose, and why

The surface is complete by construction, not by demand: every public routine
in the domain modules is reachable from C, and the six that are not are named
here rather than left to be noticed as a gap.

| Routine | Why it stays Nim-side |
|---|---|
| `help.overview`, `help.groupHelp`, `help.findGroup` | The CLI's own help text, not a property of the library. A caller that embeds the engine writes its own. |
| `cli.runCli` | Parses argv and writes to stdout. A C caller reaches the same operations directly and formats the result itself, which is the point of having an ABI. |
| `cli.requestCancel` | Sets the CLI's process-wide cancel flag from a signal handler. The ABI passes a per-call `um_cancel_fn` instead, so two concurrent calls can be cancelled independently. |
| `types.checkCancelled` | Takes a Nim closure. Its C equivalent is the `um_cancel_fn` every long operation already accepts. |

Adding a public routine to a domain module without either exposing it or
adding a line here leaves the surface incomplete, which is the state this
table exists to make visible.

## Why now, and what is not yet true

ADR-0003 set five conditions. They are not all met, and this ADR does not pretend
otherwise.

| # | Condition | State |
|---|---|---|
| 1 | Schema and migration policy survived a released version | **Not met.** Nothing is released: no tag, no remote. |
| 2 | Scan/organize/undo/dedup error categories closed and documented | Met. Exit codes `0/1/2/3/4` are documented; four migration tests cover the chain to the current schema, 17. |
| 3 | Cancellation and thread ownership tested | Met at the engine level: cancellation through the progress hook, and a test in which a worker thread opens its own store on a library whose owner keeps one open. A handle is a store, so the ABI inherits the property; nothing spawns a thread through the ABI itself. |
| 4 | Minimal ABI exposes opaque handles without leaking allocations | Met. `um_library` is opaque, every buffer comes back through `um_buffer_free`, and no SQLite handle or Nim object crosses. |
| 5 | C header/test plus a Cython wheel | Met, and over the whole surface rather than one subset: `include/UniMedia.h`, `tests/c/test_abi.c` and a wheel built by `nimble pyWheel`. |

Condition 1 cannot be met on its own terms — a first release is what the ABI is
being opened *for*. It is replaced by a stronger structural guarantee: **the
bindings never expose the schema.** No table, column, migration number or SQLite
handle crosses the boundary, so schema churn cannot break a linked application.
That is what condition 1 was protecting against, and versioning the ABI
separately protects against it without waiting for a release that depends on it.

Condition 3 was the one prerequisite that had to land before any mutating call
was exposed, and it did.

## Constraints

Inherited from ADR-0003 and non-negotiable:

- Opaque handles only. Nim objects, `Store` and SQLite handles never cross.
- Explicit ownership: every handle has one documented destructor.
- Thread-local error state; no error propagates as a Nim exception.
- Two-call pattern for UTF-8/JSON output buffers, so the caller owns allocation.
- Versioned option structs; fields are appended, never reordered or removed.
- The owner of a library handle is the thread that opened it, unchanged from
  ADR-0003.

The Python layer is a thin Cython wrapper over the same ABI, never a second
implementation. What C cannot reach, Python does not reach either.

## Surface, and what it deliberately leaves out

**The ABI reaches the library's whole subject, not the parts a first consumer
asked for.** Eighty-three entry points, every one of them reachable from Python
as well:

| family | what it reaches |
|---|---|
| library | open, close, exists, initialise, configuration, versions, error |
| catalogue | scan, paged listing, one item, its absolute path, search, filter, place facets, free-form metadata |
| duplicates | find, review, keep, remove, remove one |
| organising | plan, apply, undo plan, undo apply |
| curation | one item's curation, a batch, keywords |
| dates and places | date plan and apply, GPX plan and apply, geocode plan and apply |
| privacy | audit, strip plan, strip apply |
| integrity | audit |
| thumbnails | the one raster contract |
| albums | list, one, items, create, rename, delete, add, remove, cover |
| smart albums | list, one, items, create, rename, delete |
| people | list, faces, create a person, assign, name, clear, cluster |
| time | timeline by day, month or year |
| sync | manifest, availability, plan, apply, history |
| vision | annotations, describe, semantic search |
| media and audio | probe a video, availability of each optional tool, fingerprint, similarity |

Adding a capability to the library means adding it here in the same change.
"When a consumer needs it" is how a binding falls permanently behind the
library it binds, and this ADR previously said exactly that about albums,
people, vision and sync — four families a cataloguing application obviously
wants.

### What stays Nim-side, and why

Each of these is reachable from Nim only, for a reason specific to it:

- **Internal helpers that happen to be exported** — `types.isoNow`,
  `types.checkCancelled`, `types.defaultLibraryConfig`, `catalog.isInternal`,
  `catalog.categoryFor`, `catalog.mediaDate`, `catalog.parseFilenameDate`,
  `store.checkedPathUnder`, `organize.newBatchId`. They are exported so sibling
  modules and the test suite can reach them, not because a foreign caller has
  any use for them.
- **Recovery that runs by itself** — `curation.recoverCurationOps`,
  `organize.recoverInterruptedBatches`. The next call performs them; exposing
  them would invite a caller to run recovery at the wrong moment.
- **Validation the ABI already performs on the way in** —
  `curation.validateCurationPatch`, `dedup.planDedupRemoval`,
  `people.replaceFaces`. Each is a step inside an entry point that exists.
- **A narrower form of something exposed** — `store.listItems` (the paged
  listing is exposed), `sync.parseSyncManifest` and `sync.diffSyncManifests`
  (the manifest is exposed as JSON, and a caller compares two of them),
  `external_audio.parseFpcalc`, `gpx.parseGpx` (the plan and apply calls take
  the file).
- **The engine behind the one raster contract** —
  `external_media.decodeMediaFrame`, `hashing.perceptualHashInfoFile`,
  `hashing.videoFrameHashes`, `face_detect.detectFaces`. Thumbnails, hashes and
  faces cross as results; the decoders that produce them do not, because a
  frame or a signature crossing the boundary would be an allocation contract
  for something the caller cannot use without the rest of the engine.
- **The lower half of the vision stack** — `vision.ollamaDescribe`,
  `vision.ollamaEmbedding`, `vision.parseOllamaDescription`,
  `vision.semanticSearch`, `vision.storeVisionDocument`,
  `vision.storeVisionAnnotation`, `vision.indexVisionText`. Describing an item
  and searching by meaning are exposed; the calls that talk to a model or write
  a row are how those two are built.
- **`catalog.addVirtualItem`** — an entry with no file behind it, which the
  library uses for its own bookkeeping. A foreign caller adding one would
  produce an item no scan can ever reconcile.
- **`config.readConfig`** — the configuration crosses as JSON through
  `um_config_json`, which is the shape that cannot break when the file's
  layout does.

Two conventions hold across every addition. An array or a report crosses as
**one JSON string** the library allocates and `um_buffer_free` releases, so an
operation with a cost happens exactly once and no schema crosses. And an
out-parameter that is a plain number — a count, a flag, an identifier — is
written directly, because wrapping an integer in JSON would be ceremony.

## Consequences

CI gains the two jobs the rest of the family runs: one building the static
library and compiling a C test against the header, one building and testing the
wheel. The ABI carries its own version. Breaking it is a major bump of that version
rather than of the package, and **adding an entry point raises it too**: a
caller tests the number to learn whether a call it wants exists, which it
cannot do if the number stands still while the surface grows.

`README.md`, `AGENTS.md` and the book stop stating that no bindings exist.
